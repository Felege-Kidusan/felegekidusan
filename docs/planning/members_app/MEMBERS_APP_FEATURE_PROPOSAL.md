# FKSS Members App — Proposed Feature List (FOR OWNER REVIEW — not approved for implementation)
Prepared 2026‑10‑18 on owner instruction A12. Sign‑in/activation is provided by ACC (D1–D7); this list covers what a **member** sees after sign‑in. Each item: what it is → existing SSMS support (FACT from repo `9c6f84d`) → dependencies / permissions → mark.
Standing rule: members are **never registered in the app** (web dashboard only).

## Cross‑cutting dependencies
1. ACC P3 (`/api/member/v1`, Members app shell) must exist first (D7 §9.1).
2. Authorisation model: every endpoint scoped by the token `sub` → one `member_id`; no member‑to‑member lookups; minors' profiles follow the same rules as adults (own data only).
3. Feature flags per area (`FEATURE_MEMBER_PROFILE`, `…_FAMILY`, `…_ANNOUNCEMENTS`, `…_CALENDAR`, `…_ATTENDANCE`, `…_NOTIFICATIONS`) so the owner can enable areas independently.
4. Items 3 and 4 are the only ones needing **new staff‑side features and tables**; items 1, 2, 5, 6 are read‑only over existing data plus ACC tables.
5. Amharic UI strings throughout; Ethiopian dates via existing helper; low‑end‑device friendly (no heavy media in Phase 1).

## Suggested Phase‑1 cut for owner review
Phase 1: 1 (view + correction request), 2 (read‑only), 5, 6 (in‑app inbox; push if decided).
Phase 2: 3 and 4 with their staff authoring screens.
